6. Expert y SRP en decisiones concretas

Expert

  • Player modifica su propia vida y Ether.
  • Deck roba porque conoce el orden de sus cartas.
  • Creature calcula sus estadísticas porque conoce sus bases y mejoras.
  • Game cambia el jugador activo porque conoce a los participantes.
  • CombatResolver compara ataque y defensa porque necesita dos criaturas.

SRP

  • Si cambia el combate, cambia CombatResolver.
  • Si cambia un hechizo, cambia su Effect.
  • Si cambia un dado, cambia ese tipo de dado.
  • Si cambia el límite de mano, cambia Hand o la regla de fin de turno.
  • Game no calcula daño ni interpreta cartas.

7. Secuencias de colaboración

Inicio de partida

Facade → UsersRepository → User → Player → Game → preparación de Deck y Hand.

Jugar una carta

Facade → CardPlayService valida fase, jugador, carta, costo y objetivo → Player paga Ether → la carta cambia de zona → EffectResolver ejecuta sus efectos.

Combate

Game identifica los roles → se crean Attack → CombatResolver lanza IDice → calcula valores efectivos → aplica daño o destruye criaturas → Game verifica el final.
